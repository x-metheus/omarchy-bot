# 17: Network policy and credential hardening

**What to build:** Four places where the app or tooling trusts more than the spec allows are tightened, so that a token cannot leak and the user cannot be tricked into an unauthenticated install:

1. **Unpaired CSP.** Before pairing, the app's page may connect only to loopback HTTP and HTTPS origins needed for the pairing exchange, not to `http:`/`https:` everywhere. Plain HTTP to a non-loopback host is never allowed by the page, matching what the Rust address validation already refuses.
2. **No silent memory shell in the app.** In the packaged app, a missing or broken native shell is a visible startup error. The Web UI never falls back to the memory shell, so the device token can never land in `localStorage`. The Vite harness and Chromium tests keep using the memory shell explicitly.
3. **Installer authenticity.** When the installer downloads the Omarchy Bot AppImage, it verifies the AppImage's updater signature against the release public key built into the installer, not only a `.sha256` from the same origin. A missing or invalid signature aborts the app install and leaves the Service install intact, with a clear message.
4. **Container-only CA trust.** The Linux app smoke session updates a CA trust store only when it can prove it runs inside the repository's container. Run as root on a host, it refuses (AGENTS.md host safety).

## Comments

Unpaired CSP now allows only `/api/pairing/exchange` on canonical loopback HTTP and arbitrary HTTPS; non-loopback `http:` origins are refused. Recorded exception, as the criterion allows: a static policy cannot name an arbitrary HTTPS pairing target because the Service address is entered after the page loads, so the narrowest workable policy is an unrestricted HTTPS host with the exchange path restriction. The paired CSP is unchanged. WebKit's limits on literal IPv6 and other 127.x loopback forms are documented; no native transport was added.

In the packaged app a missing or malformed native shell is a visible startup error and the Web UI never falls back to the memory shell, which is now selected only explicitly by the dev harness and Chromium tests. The installer verifies the downloaded AppImage's real minisign prehashed Ed25519 signature against the installer-adjacent packaged trust key and its checksum before publication, refusing wrong, missing, malformed or tampered input while preserving the Service, app data and database; release packaging (`RELEASE_BUILD=true` or the `main` publication condition) validates a real `TAURI_UPDATER_PUBKEY` and fails closed when unprovisioned, while default/non-publication archives are keyless. The Linux smoke CA-trust script proves repository container markers and drops privileges before writing. Desktop-entry INI parsing is shared in one place, and the revoked-device message reads "This app's pairing was revoked."
