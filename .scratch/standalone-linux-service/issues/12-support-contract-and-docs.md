The README now documents the `systemctl --user edit` drop-in, then `daemon-reload` and an explicit restart (an edit does not change a running unit), plus `-e` variables for the container, and states the shipped CLI limitation instead of implying TLS works through `install`.

In the container, the entrypoint only starts `serve.sh` — it never runs the installer or prints a pairing URL — so the client must be paired over loopback HTTP before TLS is enabled and the container restarted on the same volume; a fresh TLS-only container cannot issue a code through this CLI.
- **Orphaned Sidecar contract.** ADR 0011 and the README now list the required `OMARCHY_BOT_DEVICE_TOKEN` alongside `OMARCHY_BOT_DAEMON_PORT` and `OMARCHY_BOT_SIDECAR_ROOT`.

### 2026-10-27 — limitations superseded by ticket 16

The CLI/doctor/TLS/container limitations recorded above described the code shipped when this ticket was resolved. [Ticket 16](16-cli-hardening.md) changes that behavior on its own branch, so those sentences are superseded rather than deleted from this record:

- `doctor` now checks the installed runtime files, the `.archive-sha256` marker format, the pinned Sway bundle ready marker, the required fonts, the unit and launcher, `GET /api/health`, and an unrevoked Paired Device in addition to prerequisites; it exits 1 on any required failure and prints `All required checks passed.` when only the advisory linger hint remains. It still changes nothing and still does not rehash installed files.
- `pair`, `devices`, `revoke`, `status`, `doctor`, and the `install`/`update`/`reconfigure` health wait follow the configured scheme, so they work against a TLS-bound Service. Self-signed trust applies only to a loopback destination; a specific local interface binds its source to loopback for the Service's host authorization while still verifying the destination certificate, and redirects are refused.
- `install`/`update`/`reconfigure` accept `--tls-cert`, `--tls-key`, and `--trusted-proxy` with `OMARCHY_BOT_TLS_CERT`, `OMARCHY_BOT_TLS_KEY`, and `OMARCHY_BOT_TRUSTED_PROXY` fallbacks, write them into the unit, and persist connection settings in `<dataDir>/service.json`. The `systemctl --user edit` drop-in recipe is no longer needed for TLS, though inherited-environment Launchers are unchanged.
- `install` writes an executable `~/.local/bin/omarchy-bot` launcher (no `PATH` or shell-startup edits) and `uninstall` removes it, so there is a real `omarchy-bot` command; `--help`, `-h`, `help`, and per-command help exit 0.
- A TLS container prints one `pairing:` URL on first start with no active Paired Device, and `docker exec … pair`, `devices`, and `revoke` work over HTTPS; a wildcard bind goes through loopback, and a specific interface keeps a loopback source while verifying the destination certificate.
