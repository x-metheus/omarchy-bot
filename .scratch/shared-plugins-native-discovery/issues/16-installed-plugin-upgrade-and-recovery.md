# 16: Deliver complete fresh-install and upgrade plugin workflows

**Parent:** [Shared Plugins, Native Discovery, and Default Cross-Agent Skill Creation](../spec.md)

**What to build:** An installed product starts with working shared plugin behavior and default Pi-only Skill creation, while an existing user can upgrade without losing shared Skills, custom MCPs, account identity, local edits, or conversations. Restarts and multiple Bots use the same effective environment. This closes cross-slice distribution and migration gaps; it does not postpone the individual tickets' behavior or tests until the end.

**Blocked by:** [05: Share native Skill discovery and creation across Agents](05-cross-agent-skill-discovery-and-creation.md); [08: Synchronize shared MCP entries across native client formats](08-cross-agent-mcp-synchronization.md); [09: Let Bots manage custom MCP connections](09-bot-custom-mcp-management.md); [11: Deliver official Google Drive, Gmail, and Calendar Services](11-official-google-services.md); [12: Deliver official Notion, GitHub, and Linear Services](12-official-notion-github-linear-services.md); [13: Deliver official Asana and Dropbox Services](13-official-asana-dropbox-services.md); [14: Apply official-only behavior to HubSpot, Intercom, and Miro](14-official-hubspot-intercom-miro-services.md); [15: Automatically update plugins without overwriting local work](15-safe-automatic-plugin-updates.md).

**Status:** ready-for-human

**Spec coverage:** User Stories 43, 57, 72, 75, 76, 77, 78, 79. Apply the parent specification's domain, host-safety, credential, and behavioral-verification constraints throughout.

- [ ] Exercise the actual packaged/product startup path in a fresh isolated Pi-only environment, not just a development import. Default Creator resources and the selected Pi MCP extension are available without user manual installation or Codex/Claude prerequisites.
- [ ] Demonstrate the fresh-install user flow: one Bot searches/installs a Skill and manages a custom MCP, creates a new local Skill through the default Creator, and another Bot uses the shared results. The open Client shows changes and effective reload/auth conditions without losing the Thread or Composer draft.
- [ ] Exercise an upgrade from the existing managed-plugin layout with complete Skill companion files, disabled choices, custom stdio/remote definitions, multiple account identities, local edits, and a conflicting native resource. Preserve those data and report conflicts without overwriting or silently resetting setup.
- [ ] Verify provider cutovers do not erase unrelated grants or independent resources, and previously available self-maintained REST paths are not retained as hidden official fallbacks. Ineligible official Services are visibly unavailable for an evidenced reason.
- [ ] After upgrade and repeated restart, native project configuration, Client inventory, and effective runtime behavior converge. Deletions do not resurrect; unchanged resources do not duplicate; no MCP call or Skill is registered through both obsolete injection and the new native path.
- [ ] Exercise restart/interruption during synchronization or update and prove preservation of the last usable content and newly made local edits. Different Bots keep independent Native Sessions, and deleting the creator Bot does not delete shared Skills or configuration.
- [ ] Run the complete cross-client compatibility scenarios delivered by the earlier tickets with actual target client versions. Keep Pi-only acceptance independent. Missing native clients, model access, provider registration, or live credentials are explicitly recorded as unverified prerequisites, never counted as passed fixture evidence.
- [ ] Verify actual desktop and narrow-layout Client behavior across grouped Services, independent MCPs/Skills, Bot/file-originated changes, authorization needs, conflicts, and update attention. Do not claim Tauri/WebView compatibility from Chromium results.
- [ ] Finish distribution/configuration changes needed for installed execution and reconcile current support/runtime documentation with the native-discovery cutover. Remove remaining obsolete paths that this feature actually replaces; no permanent duplicate runtime, synthetic Skill aliases, or contradictory blanket reload guarantees remain.
- [ ] Record installed source/extension/client revisions and exact observed scenarios. Existing individual-ticket regressions stay focused on external behavior; do not replace them with a broad source-text audit or a generic all-green claim.
- [ ] All scenarios use isolated homes, workspaces, credentials where applicable, and project-managed or temporary dependencies with targeted teardown. Do not alter host package installations, user-global Agent configuration, Host Session services, compositor state, shared unrelated work, or existing Native Sessions.
- [ ] Do not add Codex/Claude Bot workers, a new creation/publishing service, an alternative Client, or unrelated desktop/memory capabilities while resolving final integration problems.
