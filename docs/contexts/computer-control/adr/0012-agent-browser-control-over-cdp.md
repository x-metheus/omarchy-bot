# Drive the pack browser over a private CDP pipe

Status: accepted on 2026-10-28; amended on 2026-11-03 to join known Screen owners to native windows with unique temporary title stamps. All Bots share one pack browser and profile. Natural titles and dimensions never infer ownership. Extends [Computer ADR 0010](0010-daemon-owns-bot-computer-input.md) and [Computer ADR 0011](0011-bundle-one-sway-bot-computer.md); it does not change the shared Bot Computer, routed Screens, serialized seat, or the pack default. Its host-browser paragraph is superseded by [Computer ADR 0013](0013-bots-use-only-the-pack-browser.md): the pack is the only Bot browser, so the Browser Tool is available on every Service Host. Implementation is tracked by [ticket 17b](../../../../.scratch/standalone-linux-service/issues/17b-browser-agent-tools.md) under [the standalone Linux Service specification](../../../../.scratch/standalone-linux-service/spec.md).

Amended on 2026-11-03 (revised title-stamp design): one ownership registry serves Sway routing and the Browser Tool. Owners come from a Bot launch, a page's opener, or the specific Screen whose Web Control input lease the user holds. Every new eligible pack toplevel is parked immediately, including launches. The daemon stamps each candidate page with a distinct nonce in an isolated world, observes that exact title in Sway, restores the real title, then moves and verifies the matched container without changing seat focus before registering it. A stamp has a two-second deadline and one retry; failure leaves the window parked and unowned and gives a waiting Bot a clear retryable error. This supersedes the earlier exactly-one-pending/five-second/window-count correlation rule. The Element Ref and selected-tab visibility rules are unchanged.

Agents could already see a Bot Screen as pixels and act through raw input. That is enough to recognize a page and not enough to operate one reliably: element identities, names, values, and states are invisible, and a typed value or a click may land on the wrong thing after a reflow. The pack browser is the one browser the Service owns, with a known version and a known launch flag set, so it can also expose its structure without relying on host policy.

The daemon launches that pack browser with `--remote-debugging-pipe` and drives it over the two extra child descriptors Chromium defines: commands on fd 3, replies on fd 4, NUL-delimited JSON. No TCP debugging endpoint is opened, so nothing on the host or network can attach to a Bot's browser. One in-process runtime adopts the live pack pipe and scopes target and element access to windows registered for each Screen; `tabs` spans all that Screen's windows. The one registry joins exact Sway container ids to Chromium window ids, with no competing Browser Tool adoption path.

Target discovery observes page `openerId`: its registered opener window or still-pending opener target supplies the owner even when another Screen holds focus. A launch or popup may therefore open a child before its own native window has completed attribution; both targets keep the same Screen lifetime and independently require exact stamps. Each Browser Tool call can cancel its own wait for shared target discovery, including on Screen closure or action deadline, without cancelling discovery for other callers. Targets created by a Bot launch use that Bot's Screen; targets created during human Web Control use that lease's specific Screen, with controller kind, epoch and Computer generation carried through the runtime boundary. Bot input authority or native focus alone grants no human owner. An ordinary tab joining an already-owned Chromium window keeps that window's owner and needs no native-window attribution.

The Bot Computer's prepared `BROWSER`, MIME handler and browser-name shims dispatch URLs on demand over a mode-0600 Unix socket in its private runtime directory. The daemon captures an existing live Bot launch or the specific Web Control lease at receipt; callers provide URLs, never a Screen identity. With neither authority the request is refused. A cold request reuses the daemon's `open_url` launch lifecycle, so the first pack process already has its adopted private CDP pipe and shared profile. It does not preopen a browser for Web Control or ordinary applications. A handler invoked within an ordinary Bot application launch shares that launch's target claims; its stamp binding remains independently cancellable. The handler is closed with the Computer, and replacement adapters replace only their own in-process listener or a socket proven stale, refusing a listener owned by another daemon.

On subscription replacement, the listener is installed before rereading the native tree. Existing eligible unowned pack toplevels pass through the same guarded, deduplicated parking path as new events, recovering windows mapped during the subscription gap. A child whose opener ownership lookup is still in flight waits within the bounded, cancellable lookup deadline and rereads pending or registered ownership against the captured Screen lifetimes. Each native window still needs its own exact stamp.

On every unowned pack `window::new`, Sway parks the container on its scratchpad immediately. For each candidate page awaiting a window, the daemon creates an isolated world, saves `document.title`, and evaluates `document.title = nonce` with a unique nonce. It observes an exact title stamp on an eligible parked Sway container through title events or tree rereads, checks the CDP window identity again, and restores the real title before movement. The document stamp is always the bare nonce. A native title must equal either that entire nonce or exactly `nonce + " - Google Chrome for Testing"`, the fixed decoration emitted by the pinned pack; arbitrary prefixes, suffixes, other browser branding and partial nonce matches are rejected. Distinct nonces allow simultaneous popups with the same natural title, process and dimensions to be joined independently. Only a still-live candidate may reserve the exact native/CDP pair, move it to its owner's workspace, verify the move without focusing a window or workspace, and register ownership. Restoration is conditional on the title still being that attempt's nonce, so a later page title is preserved; navigation cancels the old document attempt and retries with a new isolated world. Screen/target/Computer cancellation prevents stale registration and runs bounded restoration/reparking cleanup.

Each stamp attempt has about two seconds and retries once. Authoritative target destruction immediately cancels and cleans up the current attempt; the retry runs a bounded liveness preflight and may end immediately on that destruction evidence, without recreating the candidate or sending blind commands to the dead target. Exhaustion returns the same retryable attribution error. Screen, Computer and caller cancellation remain cancellation, including when bounded reparking cleanup fails (that cleanup failure is logged). A Bot launch's pending binding and stamp share its caller and Screen lifetime, so a cancelled launch cannot register later; cancelling a separate Browser Tool waiter stops that wait without cancelling another call's launch. Refusal, title reset, disappearance or IPC failure fails closed: the native window stays parked and unowned, every Screen's scope excludes it, and a waiting Bot receives a retryable error. Scratchpad command or verification failure is surfaced rather than recorded as successful parking. A target without an opener, pending launch or active human lease stays unowned. Candidate eligibility uses `BrowserSupply.isPackBrowser(pid)`: the pack binary or its descendants, consistent with ADR 0013. Process identity never assigns Screen ownership. Natural page titles, geometry, pending counts, event age and CDP window counts never select an owner or substitute for the exact nonce match. The selected tab is read from each candidate tab's isolated-world `document.visibilityState`, and an unclear selection fails closed. Wayland Chromium reports global window `left`/`top` as zero, so CDP coordinates do not map windows to outputs; routing comes from Sway.

Agents get a `browser` tool beside `computer`: `snapshot` returns the accessibility tree with refs, roles, names, values, and states, and `click`, `type`, and `select` accept a ref from the latest snapshot. An Element Ref is valid only until the next snapshot, navigation, tab change, or document replacement; a stale ref fails and tells the Agent to take a new snapshot rather than guessing a selector. `navigate`, `back`, `read_text`, `tabs`, and `wait_for` cover page, history, text, tab, and waiting needs, with byte caps so a large page cannot flood the Turn. `wait_for` tests a condition against the full page text without returning it, so its text search is not limited by the `read_text` cap; `read_text` and `snapshot` stay capped, and a worker result states when truncation omitted content.

Structure first, pixels as fallback. The `browser` tool is the preferred interface for ordinary pages; screenshots and raw input remain available for canvases, custom widgets, and anything the accessibility tree does not describe. `click`, `type`, and `select` are real input at the element's on-screen position through the existing daemon input path and its serialized seat: the element is scrolled into view, its box is mapped from inner viewport coordinates (including scrollbar gutters) to the routed window, and the pointer or key event travels through the same helper as a `computer` action. They never call page `.click()` or assign a value.

Launching adds no automation signal of its own: the pack window uses the same non-automation flags as `open_url`, page targets never receive `Runtime.enable`, and page scripts run only in isolated worlds created by the Service. No startup script is registered on page documents and no main-world evaluation is performed, so a page cannot observe Service script through its own globals. The one signal it cannot omit is `navigator.webdriver`: Chromium sets it to true for any launch with `--remote-debugging-pipe`, before a client attaches. The Service accepts that and does not spoof the value or pass `--disable-blink-features=AutomationControlled` to hide it, because `navigator.webdriver` is the standard way a browser tells sites it is automated, hiding it starts an evasion arms race this design declines to join, and anti-bot vendors weigh many other signals anyway. Sites that challenge the Bot because of it are handed to the user through `request_takeover`. A TCP debugging endpoint would avoid the signal but was rejected because any local process could take over the Bot's signed-in browser.

Every browser action goes through the Computer Broker under the same per-Screen serialization and Takeover rules as `computer`. A user Takeover holds a pending browser call exactly as it holds a computer call, and the call resolves with a fresh snapshot instead of a stale screenshot when the user selects “I'm done.” An Agent that meets a CAPTCHA, an anti-bot challenge, a login, or a payment step calls `request_takeover` with a short reason. The call first confirms the Screen runtime is ready and that the browser pack is installed (otherwise it fails with the missing-pack error), before anything is held; it does not require an already-open browser window. The invocation then stays pending, Web Control and the Computer Surface show the reason, and the Agent resumes from a fresh snapshot after the user is done. A Bot never tries to solve or bypass a challenge.

The pack browser is launched as a directly owned session child rather than through the transient-unit path used for ordinary applications. `systemd-run --pipe` cannot forward the extra descriptors the CDP pipe needs, so `ApplicationUnits` does not apply to that launch; existing tracked-child teardown still stops that browser's process tree with the Bot Computer. The shared Bot Computer browser profile of Computer ADR 0009 is unchanged, so sign-ins carry across Screens.

A host browser has no Service-owned pipe, an unknown version and flag set, and may be Firefox, which removed CDP. Computer ADR 0013 therefore removes host browsers from the Bot Computer entirely; a Service Host without the pack reports the missing pack instead of falling back.

## Considered Options

- **Add a browser-automation dependency (Playwright, Puppeteer, or a CDP client library)**: rejected; each brings its own browser download or launch policy, and the Service already owns the exact pack binary, profile, and launch flags. A small NUL-framed JSON client is the whole requirement.
- **A TCP `--remote-debugging-port` endpoint**: rejected; it exposes the Bot's browser to anything that can reach the port, needs an extra listener and cleanup, and gains nothing over the inherited pipe.
- **Drive clicks and typing with page script (`.click()`, value assignment)**: rejected as the primary path; it bypasses the serialized input seat and Takeover, and pages can detect or override it. Real input keeps one arbitration model for `computer` and `browser`.
- **A headless agent browser such as Lightpanda as the default**: rejected for the Bot Screen; the user must be able to watch and take over the same window. It remains a possible separate background tool.
- **WebDriver BiDi**: rejected; the pack is Chromium, Firefox is out of scope, and BiDi would require a different driver and transport for no additional capability here.
- **Treat challenges as an Agent problem**: rejected; the Service does not ship stealth or bypass behavior, and a person is both more reliable and the correct authority for a login or payment.

## Consequences

- The `browser` tool contract lives in `packages/agent-contract` beside `computer-tool.ts` and is exposed by real (Pi) and scripted workers.
- Snapshot text is capped (about 16 KiB / 300 nodes) and `read_text` about 8 KiB; truncation is reported so an Agent can narrow its snapshot rather than assume completeness.
- Screen ownership uses one registry and exact temporary title stamps for Bot launches, opener-owned popups and human Web Control windows. Every eligible unowned native window is parked before attribution; movement and verification restore its title and preserve seat focus. A missing owner or two failed stamp attempts leaves it unowned and excluded from every scope, with a retryable waiting-Bot error. Natural titles, dimensions, focus, timing and window counts confer no ownership. Selected-tab visibility and Element Ref lifetime still fail closed under the existing isolated-world rules.
- Chromium's singleton behavior means a repeated `open_url` may hand off to the existing browser process; the adopted runtime stays attached while that process lives.
- Sites can still challenge or block the Bot. IP reputation, datacenter or VPS addresses, and site policy are often the deciding factor and are outside the Service's control, and `navigator.webdriver` is true by design, so sites that check it may challenge the Bot more often.
- Losing the pipe to a daemon restart has no reconnect path; the browser must be relaunched and the failure is reported rather than masked.
- There is no host-browser path for the browser tool to skip (Computer ADR 0013); without the pack, `browser` and `request_takeover` report the missing pack.
