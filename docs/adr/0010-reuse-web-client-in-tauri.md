# Reuse the Web client in a future Tauri desktop client

Status: accepted on 2026-09-05; Omarchy Bot (Tauri) is future delivery, not implemented by this decision. Amended on 2026-10-24: execution stays on the Service ([ADR 0013](0013-run-a-standalone-linux-service.md)) rather than "the Omarchy side", and the network contract is paired device tokens ([ADR 0014](0014-require-paired-device-tokens.md)). Amended on 2026-10-28 by [ADR 0015](0015-omarchy-bot-app-is-the-only-bot-client.md): Omarchy Bot is delivered as the only Bot Client, the Web UI is embedded in it, and the browser is no longer a client.

The current Web frontend is the foundation of Omarchy Bot, rather than a disposable prototype or a second product to rewrite. Conversation UI, Bot selection, Computer Surface behavior, and daemon-facing contracts remain shared; Tauri supplies a client shell, while Agents, Native Sessions, the Bot Computer, routed Bot Screens, and desktop input execution remain in the Service ([ADR 0013](0013-run-a-standalone-linux-service.md)). This avoids duplicating business behavior or moving host desktop responsibilities into the viewer. The application is named Omarchy Bot, not Desktop or Desktop Client ([ADR 0011](0011-local-sidecar-only-off-host.md)).

The current [implementation specification](../../.scratch/shared-workspace-desktop-boundary/spec.md) preserves this client/execution separation but does not ship Tauri packaging, native capabilities, or auto-update, and makes no platform support promises. Pairing ships with the Service ([ADR 0014](0014-require-paired-device-tokens.md)). Future Tauri delivery must verify its actual WebView projection and input behavior; existing Chromium tests do not prove noVNC/RFB compatibility. This agreement changes neither the Service's network contract, which is paired device tokens ([ADR 0014](0014-require-paired-device-tokens.md)), nor the install-only lifecycle of the Omarchy plugin. When that client is built, a Local Sidecar starts only off the plugin host, as recorded in [ADR 0011](0011-local-sidecar-only-off-host.md).

Reach this decision from [CONTEXT-MAP](../../CONTEXT-MAP.md#system-wide-decisions). Do not add native scaffolding or claim WebView compatibility as part of the current correction.
