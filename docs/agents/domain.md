# Domain documentation

Omarchy Bot uses one glossary for all apps and packages. Before exploring a change, read `GLOSSARY.md` at the repository root when it exists. Use its terms in issue titles, design proposals, code, and tests. If the glossary is absent, proceed with the task. Use `/domain-modeling` to record an agreed definition when a term needs clarification.

Read the decisions relevant to the change in [docs/agents/adr/](adr/). If a proposal conflicts with a decision, cite the ADR and explain why it is worth reopening. Record new architectural decisions there when they are settled.

Older `.scratch/` records cite decisions by number. The [archived documentation tree](https://github.com/x-metheus/omarchy-bot/tree/6750011404c8032470a169e52bf7ebe362a88e4c/docs) contains the system-wide and per-context decisions from that period.
