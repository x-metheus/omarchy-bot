# Domain documentation

Metheus uses one glossary for all apps and packages. Before exploring a change, read `GLOSSARY.md` at the repository root when it exists. Use its terms in issue titles, design proposals, code, and tests. If the glossary is absent, proceed with the task. Use `/domain-modeling` to record an agreed definition when a term needs clarification.

Ground future design proposals in current product behavior, the root glossary, accepted ADRs, and current approved requirements. Use the [code map](../README.md#code-map) to find the implementation and tests. Read the relevant approved specification in [GitHub Issues](issue-tracker.md) and any current files it links in `docs/specs/`.

Read the decisions relevant to the change in [docs/agents/adr/](adr/). If a proposal conflicts with a decision, cite the ADR and explain why it is worth reopening. Record new architectural decisions there when they are settled.
