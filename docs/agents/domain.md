# Domain documentation

Omarchy Bot uses one glossary for all apps and packages. Before exploring a change, read `GLOSSARY.md` at the repository root when it exists. Use its terms in issue titles, design proposals, code, and tests. If the glossary is absent, proceed with the task. Use `/domain-modeling` to record an agreed definition when a term needs clarification.

Read the decisions relevant to the change in [the shared ADR directory](../adr/). If a proposal conflicts with a decision, cite the ADR and explain why it is worth reopening. Record new architectural decisions there when they are settled.
